# Codex 작업 지시서 — 알킨스 채용관리 시스템

당신은 (주)알킨스 경영지원팀의 사내 채용관리 웹앱을 개발한다.

## 최우선 목표
현업 유관자에게 새로운 업무를 만들지 않는다. 경영지원팀이 전체 흐름을 관리하고, 요청부서장과 면접관은 필요한 순간에 필요한 화면만 사용한다.

## 기술 스택
- Next.js App Router + TypeScript + Tailwind CSS
- Supabase(PostgreSQL/Auth/Storage)
- 배포: Vercel 또는 사내 서버
- 모바일에서도 면접평가가 쉽게 가능해야 함

## 역할
1. HR_ADMIN: 전체 권한
2. REQUESTER: 본인 부서 채용건 조회/의사결정
3. INTERVIEWER: 배정된 면접과 평가만 조회/작성
4. VIEWER: 필요시 읽기 전용

## 필수 기능
### 채용요청
- HR-YYYY-NNN 자동 채번
- 요청부서, 직무, 인원, 충원사유, 주요업무, 필수/우대사항, 목표입사일
- 요청부서가 직접 길게 작성하지 않아도 HR이 메모 기반으로 등록 가능

### 지원자
- 채용건별 지원자 등록
- 지원경로, 경력, 연락처, 이력서 파일
- 상태: 검토중/서류합격/서류불합격/일정조율/면접예정/면접완료/처우협의/최종합격/불합격/입사확정/입사포기
- 상세 개인정보는 권한 있는 사용자만 노출

### 면접
- 면접일시, 장소, 면접관 지정
- 면접관에게 전체 시스템이 아니라 해당 면접 링크만 전달 가능
- 안내문 복사 기능
- 캘린더 등록용 .ics 다운로드 기능 추가

### 평가
- 1분 내 입력 완료 가능
- 직무 적합성/경력·역량/조직 적합성: 우수/적합/보통/미흡
- 종합의견: 적극 추천/추천/보류/불합격
- 추가의견은 선택 입력
- 제출 후 HR이 한 화면에서 취합 확인

### 대시보드
- 진행중 채용 수
- 지원자 수
- 이번주 면접
- 입사예정
- 채용번호/부서/직무/인원/상태/다음 액션/목표입사일
- 지연 건 강조

### 유관자 부담 최소화
- 현업에게 상태 변경, 자료 정리, 중복 입력을 요구하지 말 것
- 요청부서장에게는 채용 요청 확인/서류 의견/최종 의견 정도만 요구
- 면접관에게는 면접 일정 확인 + 평가만 요구
- 알림은 행동이 필요한 시점에만 발송

## UX 원칙
- 한국어 UI
- 데스크톱은 관리 화면, 모바일은 면접평가 중심
- 한 화면에 정보 과다 노출 금지
- 선택식 우선, 서술형 최소화
- 버튼 문구는 행동 중심으로 작성

## 보안/감사 대응
- 개인정보 최소 수집
- 역할별 접근제어(RLS)
- 변경 이력 로그 저장
- 지원자 자료 접근 로그 고려
- 퇴사/권한변경 시 즉시 접근 차단 가능

## 개발 우선순위
1. Supabase 연동 및 데이터 모델
2. Auth + 역할별 권한
3. 채용요청 CRUD
4. 지원자 CRUD + 이력서 업로드
5. 면접 일정 및 면접관 할당
6. 모바일 평가 화면
7. 대시보드
8. .ics 일정 다운로드
9. 감사 로그
10. 이후 다우오피스 연계 가능성 검토

## 현재 프로젝트
현재 저장소에는 UI 프로토타입과 `supabase/schema.sql`이 있다. mock 데이터를 제거하고 실제 Supabase 데이터로 교체하라. 기존 화면의 단순한 UX 방향은 유지하되, 디자인보다 실제 운영 편의성과 권한구조를 우선한다.

## 완료조건
- HR_ADMIN이 채용요청 생성 → 지원자 등록 → 면접 일정 생성 → 면접관 평가 → 최종 상태 변경까지 수행 가능
- INTERVIEWER 계정은 본인에게 배정된 면접 외 다른 지원자 개인정보를 볼 수 없음
- 모바일에서 평가가 1분 내 완료 가능
- 모든 주요 상태 변경에 created_at/updated_at과 변경주체를 남길 수 있는 구조
