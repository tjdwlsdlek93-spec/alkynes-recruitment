# 알킨스 채용관리

기존 한국어 화면 디자인을 유지한 브라우저 저장형 채용관리 앱입니다. 처음 열면 예시 데이터가 표시되며, 등록·수정한 내용은 같은 브라우저의 같은 사이트에 저장됩니다.

## 사용 순서

1. **채용 요청** → **채용 요청 등록**: 요청부서·직무·인원을 입력합니다. 충원사유, 주요업무, 필수/우대사항, 목표 입사일을 기록할 수 있습니다. 채용번호는 한국시간 연도 기준으로 자동 생성됩니다.
2. **지원자 보기** → **지원자 등록**: 채용건에 지원자를 연결하고 경력·지원경로·연락처·메모를 기록합니다. 이력서는 1MB 이하 PDF를 등록·다운로드·삭제할 수 있습니다.
3. **지원자 상세 / 수정**: 서류 검토 결과와 진행 상태를 변경합니다.
4. **면접 관리** → **면접 일정 등록**: 한국시간 일시·장소·면접관을 지정합니다. 일정 등록은 지원자 상태에 반영됩니다. 안내문 복사와 1시간짜리 캘린더(.ics) 다운로드를 제공합니다.
5. **평가 작성 / 보기**: 배정된 면접관을 선택하고 세 가지 항목과 종합의견을 제출합니다. 같은 면접·면접관의 평가는 중복 생성 대신 수정됩니다. 평가 제출 시 면접완료로 반영되고, 최종 결정은 자동으로 내리지 않습니다.
6. **지원자 상세 / 수정**: 처우협의 → 최종합격 → 입사확정 등 결과를 반영합니다. **채용 요청 상세 / 수정**에서 채용완료·보류·취소를 직접 결정합니다.
7. **대시보드**에서 진행중 채용·지원자·이번주 면접·입사확정과 다음 액션을 확인합니다. **설정**에서 변경 이력 조회와 JSON 백업·복원이 가능합니다.

검색과 채용건·상태 필터를 지원합니다. 지원자 삭제는 확인을 거친 후 연결된 면접·평가도 함께 삭제합니다. 채용 요청은 취소 상태로 기록을 유지할 수 있습니다.

## 저장 범위

- 데이터는 서버나 Supabase가 아닌 브라우저 localStorage에 저장됩니다.
- 같은 사이트의 다른 탭에도 변경이 반영됩니다. 여러 사용자가 동시에 수정하는 업무용 서버 저장 기능은 없습니다.
- 사이트 주소/포트나 브라우저가 달라지면 별도의 데이터가 표시됩니다. 다른 기기로 이동할 때는 설정에서 백업을 내려받아 복원합니다.
- 브라우저 데이터를 삭제하면 저장 기록도 삭제됩니다. 백업 복원은 기존 데이터를 교체하므로 먼저 백업하세요.
- 저장 공간 부족 또는 저장 권한 차단 시 오류를 표시하고, 저장하지 않은 내용을 성공으로 처리하지 않습니다.
- 로그인·역할별 접근제어·보안 감사로그·알림 전송은 아직 구현하지 않았습니다. 평가자 선택은 로그인 확인이 아닙니다.
- 테스트 데이터로 사용하세요. 백업에는 연락처와 이력서가 포함됩니다. 실제 사내 운영에는 Supabase 인증, RLS, 서버 저장과 Storage 연결이 필요합니다.

## 실행

검증 환경: Node.js 24, npm 11.

```bash
cd alkynes-recruitment-codex
npm ci
npm run dev
```

프로덕션 실행은 같은 폴더에서 다음 명령을 사용합니다.

```bash
npm run build
npm run start
```

Codex 클라우드에서는 환경 설정에 저장된 설치·시작 지침을 따릅니다. 개발 원본은 /workspace/-/alkynes-recruitment-codex이고 실행 복사본은 /workspace/.onboarding/alkynes/app입니다. 원본을 수정하면 변경 파일을 실행 복사본에 동기화해야 합니다. 개발 서버와 프로덕션 서버는 같은 .next 디렉터리를 동시에 사용하지 마세요. package-lock.json으로 의존성 버전을 고정합니다. 재설치는 npm ci를 사용합니다.

## 검증

```bash
npm test
```

단위 테스트는 백업 데이터 연결 검증, 채용번호 생성, 한국시간 일정의 UTC 캘린더 변환과 UTF-8 줄 접기를 검사합니다.

별도 터미널에서 프로덕션 서버를 실행한 후 다음 명령으로 실제 브라우저 테스트를 실행합니다.

```bash
npm run test:e2e
```

기본 테스트 주소는 http://127.0.0.1:3000입니다. E2E_BASE_URL로 다른 주소를 지정할 수 있습니다. 테스트는 매번 별도 브라우저 컨텍스트에서 실행되어 기존 사용자 데이터에 영향을 주지 않습니다. 시스템 /usr/bin/chromium을 사용하거나 CHROMIUM_PATH로 실행 파일을 지정합니다. 둘 다 없는 환경에서는 npx playwright install chromium으로 Playwright 브라우저를 설치하세요.

브라우저 테스트 범위: 전체 등록·평가·입사확정 흐름, 새로고침 유지, PDF 검증, 캘린더 다운로드·안내문 복사, 백업 복원, 저장 실패, 손상된 데이터 보호, 모바일 평가, 탭 동기화, 삭제 취소·확인.

기존 npm run lint는 ESLint 설정이 없어 대화형 설정을 요구합니다. 별도의 린트 설정은 아직 추가하지 않았습니다.

## Vercel 웹 배포

클라우드 환경 게시는 웹사이트 배포와 별개입니다. 현재 작업의 수정 파일은 아직 GitHub에 업로드하지 않았으므로, 예전 저장소를 가져오는 것만으로 최신 앱이 배포되지 않습니다.

이 환경에서 배포를 진행하려면 환경 설정의 VERCEL_TOKEN 네트워크 시크릿에 Vercel 인증 토큰을 연결하고 api.vercel.com 및 \*.vercel.app 접속을 허용해야 합니다. 토큰을 저장소, .env 파일, 채팅에 넣지 마세요. 앱 자체에는 Vercel 토큰이 필요하지 않습니다.

배포 준비 상태: 의존성 고정 설치, 프로덕션 빌드 및 로컬 테스트 검증 완료. 실제 Vercel 배포와 공개 주소 확인은 인증 및 네트워크 설정 적용 후 실행해야 합니다.

환경에 준비된 /workspace/.deployment/deploy-vercel.sh는 현재 앱 디렉터리를 Vercel CLI 64.0.2로 직접 업로드합니다. 인증이 연결된 후 프로젝트 연결 대상을 확인하고 실행합니다. CLI 설정·인증 파일은 앱 외부에 저장하며 .vercelignore로 로컬 환경 파일과 테스트 파일을 업로드에서 제외합니다. 배포 완료 후 발급된 HTTPS 주소에서 실제 화면과 저장 동작을 다시 확인해야 합니다.

## 10월 14일 업데이트 Excel 연동

업무 요청 메뉴에서 .xlsx 파일을 선택하고 가져오기 미리보기를 확인한 다음 적용합니다. 원본의 채용건별 현황/채용프로세스 요약/채용프로세스 적시성 구조를 읽습니다. 원본을 수정하거나 원본 수식을 실행하지 않습니다. 처리기한은 저장된 수식 결과를 우선 읽고, 없는 경우 B11의 영업일 수로 주말 제외 계산합니다. 공휴일은 원본 설정과 동일하게 미반영입니다.

채용건명+부서, 채용건+지원자명, 요청 구분+요청일 등의 연결 키로 같은 파일을 반복 가져올 때 중복을 방지합니다. 동일 채용건 내 동명이인은 이름을 구분해야 합니다. 날짜나 요청 대상을 변경하면 새 요청으로 기록될 수 있으며, 원본에서 지운 행을 앱에서 자동으로 지우지 않습니다. 적용 전 JSON 백업을 내려받을 수 있습니다.

엑셀 연결 항목은 다시 가져올 때 원본 값으로 갱신하며 앱에서 입력한 연락처·이력서는 유지합니다. 엑셀 파일과 앱이 실시간으로 연결되는 방식은 아닙니다. 파일 수정 후 다시 가져와야 합니다. CSV 내보내기는 요청 상세 데이터 전달용이며, 원본 Excel 수식에 자동 덮어쓰지 않습니다.

대시보드의 월별 캘린더는 요청 접수, 미완료 요청 마감, 실제 면접·검사 일정 및 입력된 입사일을 보여 줍니다. 메모의 추측성 일정은 생성하지 않고 원문을 남깁니다. 취소·확인 필요·선발 단계·최종 결과를 구분하며, 이름 없는 요약 요청은 동일 채용건·전형의 지원자별 요청이 있을 때 별도 집계에서 제외합니다.

Windows 새 패키지는 install-autostart.cmd로 기존 설치를 갱신합니다. 같은 주소 127.0.0.1:8790과 같은 브라우저의 저장 기록을 유지합니다. 자동 실행 등록은 Windows에서 확인이 필요합니다.

실제 파일 검증은 KPI_TEST_FILE 환경 변수에 원본 .xlsx 경로를 지정한 뒤 npm test 및 npm run test:excel-browser로 실행합니다. 테스트에 사용된 개인 데이터는 저장소나 실행 패키지에 포함하지 않습니다.

## 2026-10-14 업데이트·Excel 자동 연결 개선

- 메뉴 이름: **엑셀 연동**. 상단의 일반 저장 안내와 저장 성공 배너는 숨기고 저장 오류는 표시합니다.
- 처음 실행해도 지정된 Excel 경로로 자동 연결을 시도합니다. 기존 패키지의 초기 중지 설정은 한 번 자동 연결로 전환합니다. 이후 사용자가 직접 중지하면 재시작해도 중지를 유지합니다.
- 파일 없음·잠금·네이버웍스 로그인 지연·저장 실패 시 연결을 끄지 않고 30초마다 다시 시도하며 마지막 정상 데이터를 유지합니다. 데이터 반영은 브라우저가 열려 있을 때 동작합니다.
- Excel 최종 결과의 지원포기·입사포기·불합격을 현재 선발 단계보다 우선합니다. 다른 요청 행의 미확정 결과가 확정 결과를 지우지 않습니다. 기존 저장 데이터도 결과를 다시 분류합니다. 지원자 기본 목록은 전형 진행중만 보여주고 불합격·지원포기·입사포기·실제 입사는 전형 종료에서 확인합니다.
- 설정에 앱 업데이트 UI를 추가했습니다. 실제 원격 업데이트에는 공개 GitHub 릴리스 저장소와 배포 assets가 필요합니다. 배포 절차: [portable/UPDATES.md](portable/UPDATES.md). 최초 한 번은 업데이트 기능을 포함한 ZIP 설치가 필요합니다.
- `npm test`는 도메인·Excel·로컬 서버·업데이트 검증/복원 테스트를 실행합니다. `KPI_TEST_FILE=... node --test tests/sync-browser.e2e.cjs`는 자동 연결 오류 후 재시도·일시중지 유지를 확인합니다.
