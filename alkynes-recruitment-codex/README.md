# 알킨스 채용관리

노트북 안에서 실행하는 개인용 채용관리 앱입니다. Windows 패키지는 Node.js 24의 SQLite 저장소를 사용하며, 채용 업무 데이터는 외부로 전송하지 않습니다. 엑셀 → 앱 단방향 연결과 기존 포스트잇 화면을 유지합니다.

## 사용 순서

1. **엑셀 연동**에서 네이버웍스 동기화 폴더의 원본 파일을 연결합니다. 채용 요청·인적성·면접 일정은 엑셀에서 등록하며, 원본은 앱이 수정하지 않습니다.
2. **대시보드**에서 진행중 채용, 전형 요청자, 주간 면접과 이번 달 입사 현황 및 캘린더를 확인합니다.
3. **채용 요청·지원자**에서 진행중/종료 기록과 공고별 현황을 확인합니다.
4. **인적성 관리·면접 일정**에서 요청 및 진행 상태, 카톡 안내문 작성·복사를 사용할 수 있습니다. 앱에서 변경한 엑셀 소유 항목은 다음 동기화 때 원본 값이 우선합니다.
5. **설정**에서 실제 저장 방식과 DB 경로를 확인하고 JSON 백업·복원을 사용합니다.
6. 좌측 하단 **앱 업데이트 / 엑셀 업데이트** 버튼으로 업데이트합니다.

## 저장 범위

- Windows 앱의 기본 저장 파일: `%LOCALAPPDATA%\AlkynesRecruitment\config\recruitment.sqlite`. 별도 실행 시 `ALKYNES_DATA_DIR` 또는 실행 폴더의 `config`를 사용합니다.
- 기존 브라우저의 같은 주소에서 업데이트 후 처음 열면 기록을 SQLite에 자동 이전합니다. 검증된 원본은 DB의 `migration_backup`과 기존 브라우저에 유지합니다. 이미 DB가 있으면 DB를 우선하며 다른 브라우저의 오래된 기록으로 덮어쓰지 않습니다.
- SQLite 모드의 업무 데이터는 localStorage에 다시 쓰지 않습니다. 브라우저 기록을 비우거나 다른 브라우저에서 같은 노트북 앱을 열어도 DB를 읽습니다. 엑셀 연결 파일은 서버의 config에 유지되며, 소량의 연결 캐시만 브라우저를 사용합니다.
- 브라우저의 약 5MB 제한을 받지 않습니다. 디스크 공간과 메모리를 사용하며 한 번의 저장 요청은 128MB, JSON 복원은 120MB, 개별 PDF 업로드는 기존과 같은 1MB 제한입니다. 무제한 저장을 보장하지 않습니다.
- 트랜잭션과 revision 비교로 실패한 저장 및 여러 창의 덮어쓰기를 방지합니다. 성공 응답 후에만 화면·엑셀 반영 완료 상태를 갱신합니다. 다른 창의 변경은 약 3초 또는 창 복귀 시 확인합니다.
- 최근 5회 이전 상태를 DB에 보관하지만 노트북 고장에 대비한 별도 백업은 아닙니다. **설정 → 백업 다운로드**로 JSON을 별도 위치에 보관하세요. DB 파일 직접 복사는 앱 서버 종료 후 수행해야 합니다(WAL 사용).
- DB 오류 시 브라우저 저장으로 조용히 전환하지 않습니다. 저장소 API가 없는 정적 웹 미리보기/이전 서버에서만 브라우저 호환 모드를 사용하며 설정에 구분해서 표시합니다.
- 서버는 `127.0.0.1`에만 바인딩합니다. 저장소 API는 Host·Origin·사용자 정의 헤더를 검사하며 config·DB 파일을 웹으로 제공하지 않습니다. 로그인이나 외부 접속 기능은 추가하지 않았습니다.
- DB 파일·엑셀·실제 개인정보는 GitHub 소스나 릴리스에 포함하지 않습니다. 앱 업데이트와 실패 복원은 config/DB를 교체하지 않습니다.

## 실행과 검증

Node.js 24, `npm ci`를 사용합니다. `npm run dev`는 UI 개발용이며 SQLite 서버가 없는 경우 브라우저 호환 모드입니다.

```bash
npm test
ALKYNES_STATIC_EXPORT=1 npm run build
npm run test:sqlite-browser
```

빌드는 공통 데이터 검증기를 `public/_server/recruitment.cjs`로 생성해 정적 site에 포함합니다. 이 파일은 생성 산출물이며 Git에는 올리지 않습니다. Windows 서버의 SQLite API는 동일 검증기를 사용합니다. 별도 SQLite 설치나 네이티브 npm 모듈은 필요하지 않습니다.

`test:sqlite-browser`는 빌드된 out과 실제 로컬 서버를 임시 폴더에서 실행합니다. 기존 브라우저 이전, 엑셀 반영, 저장 실패 후 재시도, 브라우저 저장소가 없는 새 세션, 서버 재시작, 5MB 초과 저장을 확인합니다. 실데이터는 사용하지 않습니다. 시스템 Chromium 또는 `CHROMIUM_PATH`가 필요합니다.

`E2E_BASE_URL=... npm run test:e2e`는 기존 UI·안내문·면접·엑셀 업데이트를 검증합니다. 실제 Excel 검사에는 `KPI_TEST_FILE`을 사용하며 개인 파일은 저장소에 포함하지 않습니다. 단위 테스트는 DB 유효성, 동시 저장 충돌, 트랜잭션 복원, 업데이트 후 DB 보존도 확인합니다.

이하 항목은 이전 버전의 배포·기능 변경 이력입니다. 현재 로컬 저장·운영 방식은 위 설명을 우선합니다.

## Vercel 웹 배포

클라우드 환경 게시는 웹사이트 배포와 별개입니다. 현재 작업의 수정 파일은 아직 GitHub에 업로드하지 않았으므로, 예전 저장소를 가져오는 것만으로 최신 앱이 배포되지 않습니다.

이 환경에서 배포를 진행하려면 환경 설정의 VERCEL_TOKEN 네트워크 시크릿에 Vercel 인증 토큰을 연결하고 api.vercel.com 및 \*.vercel.app 접속을 허용해야 합니다. 토큰을 저장소, .env 파일, 채팅에 넣지 마세요. 앱 자체에는 Vercel 토큰이 필요하지 않습니다.

배포 준비 상태: 의존성 고정 설치, 프로덕션 빌드 및 로컬 테스트 검증 완료. 실제 Vercel 배포와 공개 주소 확인은 인증 및 네트워크 설정 적용 후 실행해야 합니다.

환경에 준비된 /workspace/.deployment/deploy-vercel.sh는 현재 앱 디렉터리를 Vercel CLI 64.0.2로 직접 업로드합니다. 인증이 연결된 후 프로젝트 연결 대상을 확인하고 실행합니다. CLI 설정·인증 파일은 앱 외부에 저장하며 .vercelignore로 로컬 환경 파일과 테스트 파일을 업로드에서 제외합니다. 배포 완료 후 발급된 HTTPS 주소에서 실제 화면과 저장 동작을 다시 확인해야 합니다.

## 10월 14일 업데이트 Excel 연동

업무 요청 메뉴에서 .xlsx 파일을 선택하고 가져오기 미리보기를 확인한 다음 적용합니다. 원본의 채용건별 현황/채용프로세스 요약/채용프로세스 적시성 구조를 읽습니다. 원본을 수정하거나 원본 수식을 실행하지 않습니다. 처리기한은 저장된 수식 결과를 우선 읽고, 없는 경우 B11의 영업일 수로 주말 제외 계산합니다. 공휴일은 원본 설정과 동일하게 미반영입니다.

채용건명+부서, 채용건+지원자명, 요청 구분+요청일 등의 연결 키로 같은 파일을 반복 가져올 때 중복을 방지합니다. 동일 채용건 내 동명이인은 이름을 구분해야 합니다. 날짜나 요청 대상을 변경하면 새 요청으로 기록될 수 있으며, 원본에서 지운 행을 앱에서 자동으로 지우지 않습니다. 적용 전 JSON 백업을 내려받을 수 있습니다.

엑셀 연결 항목은 다시 가져올 때 원본 값으로 갱신하며 앱에서 입력한 연락처·이력서는 유지합니다. 엑셀 파일과 앱이 실시간으로 연결되는 방식은 아닙니다. 파일 수정 후 다시 가져와야 합니다. CSV 내보내기는 요청 상세 데이터 전달용이며, 원본 Excel 수식에 자동 덮어쓰지 않습니다.

대시보드의 월별 캘린더는 요청 접수, 미완료 요청 마감, 실제 면접·검사 일정 및 입력된 입사일을 보여 줍니다. 메모의 추측성 일정은 생성하지 않고 원문을 남깁니다. 취소·확인 필요·선발 단계·최종 결과를 구분하며, 이름 없는 요약 요청은 동일 채용건·전형의 지원자별 요청이 있을 때 별도 집계에서 제외합니다.

Windows 새 패키지는 install-autostart.cmd로 기존 설치를 갱신합니다. 같은 주소 127.0.0.1:8790과 같은 브라우저의 저장 기록을 유지합니다. 자동 실행 등록은 Windows에서 확인이 필요합니다.

실제 파일 검증은 KPI_TEST_FILE 환경 변수에 원본 .xlsx 경로를 지정한 뒤 npm test 및 npm run test:excel-browser로 실행합니다. 테스트에 사용된 개인 데이터는 저장소나 실행 패키지에 포함하지 않습니다.

## 2026-10-14 업데이트·Excel 자동 연결 개선

- 메뉴 이름: **엑셀 연동**. 상단의 일반 저장 안내와 저장 성공 배너는 숨기고 저장 오류는 표시합니다.

- `npm test`는 도메인·Excel·로컬 서버·업데이트 검증/복원 테스트를 실행합니다. `KPI_TEST_FILE=... node --test tests/sync-browser.e2e.cjs`는 자동 연결 오류 후 재시도·일시중지 유지를 확인합니다.

## 2026-10-15 인적성 관리·카톡 안내문

인적성 관리 메뉴에서 지원자별 요청일·처리기한·요청 처리 상태·검사 일정·검사 실시 상태·담당자·메모를 관리합니다. 같은 지원자의 여러 회차를 별도로 저장합니다. 요청 처리 완료와 검사 실시 완료는 별개이며, 완료·종료 기록은 따로 분류합니다. 기존 Excel 인적성 요청을 불러오고 원본의 검사 일시는 연결하며, 앱의 검사 실시 상태는 동일 요청 재동기화 때 유지합니다. 최초 업데이트 후에는 가져오기 스키마 변경을 감지해 기존 파일도 다시 읽습니다. 원본에서 요청이 삭제되거나 연결 키가 바뀌면 별도 요청으로 처리됩니다.

인적성·면접의 카톡 안내문 버튼에서 사내 담당자 공유/지원자 안내를 선택하고 문구를 수정·복사합니다. 자동 전송하지 않으며 카카오톡에서 직접 붙여넣어 전송합니다. 연락처·이력서·내부 메모는 기본 문구에 넣지 않습니다. 미확정 일정은 미정·확인 필요로 표시합니다. 엑셀 연동 메뉴는 설정 바로 위에 둡니다. 검사 일정은 캘린더에도 표시합니다.

검증: `E2E_BASE_URL=... node --test tests/aptitudes-browser.e2e.cjs`. 앱 수정은 Excel 원본에 쓰이지 않으며 Excel 소유 필드의 수정은 다음 동기화 때 원본 값으로 갱신됩니다.
