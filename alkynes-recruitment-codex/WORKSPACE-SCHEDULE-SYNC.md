# SEONGJIN MIN WORKSPACE 면접 일정 연동 (선택 기능)

> 현재 개인 PC에서 실행하는 채용관리 앱과 Google Apps Script 워크스페이스는 서로 다른 저장소를 사용합니다. 설치만으로 자동 동기화되지 않습니다.

## 방식
- 채용관리 PC SQLite 데이터 → **최소 면접 일정 JSON** → Google Drive 데스크톱 동기화 → GAS 워크스페이스 화면
- JSON 필드: 면접 ID, `부서 · 지원자 이름 면접`, 일시(ISO), 상태만 포함. 전화번호, 이메일, 이력서, 평가, 메모는 제외
- 60초마다 파일 다시 생성(내보내기 프로그램 실행 중). Google Drive 업로드 지연은 별도
- 워크스페이스는 열 때와 약 3분마다 Drive 파일을 읽으며, 대시보드·캘린더 상단에 **읽기 전용 일정**으로 표시
- PC가 꺼졌거나 프로그램이 중단되면 데이터 갱신 안 됨
- 중복 방지: 워크스페이스 업무 TASKS에 별도 삽입하지 않고 채용관리 일정 ID를 기준으로 화면만 표시

## 최초 설정
1. 회사 개인정보·클라우드 사용정책에서 이름/면접 일정의 개인 Google Drive 저장이 허용되는지 확인
2. 채용관리 PC에 Google Drive 데스크톱 설치·로그인 후 **본인만 접근 가능한 동기화 폴더** 생성
3. 채용관리 앱 업데이트 이후 또는 소스 환경에서, Node.js 24 이상 설치·확인
4. `alkynes-recruitment-codex` 폴더에서 다음 실행 (`G:\\내 드라이브\\SEONGJIN-SYNC`는 실제 폴더 경로로 교체):

   ```powershell
   node portable/workspace-schedule-export.cjs "G:\\내 드라이브\\SEONGJIN-SYNC"
   ```

5. 콘솔에 "면접 일정 동기화 준비: N건" 표시, 폴더에 `seongjin-recruitment-schedule.json` 생성되는지 확인
6. Google Drive 웹에서 해당 JSON을 열고 주소의 **파일 ID** 확인
7. Google Apps Script 프로젝트의 **프로젝트 설정 → 스크립트 속성**에 이름 `RECRUITMENT_SCHEDULE_FILE_ID`, 값 **Google Drive JSON 파일 ID** 등록
8. 워크스페이스 `/exec` 접속 → 대시보드 상단 '채용관리 면접 일정' 확인

**자동 시작:** Windows 작업 스케줄러에서 사용자 로그인 때 위 Node 프로그램을 실행하도록 등록하면 매번 실행하지 않아도 됩니다. 동기화 폴더 접근 가능해진 후 시작하도록 예약하는 것이 좋습니다. 업로드 완료 여부 및 저장소 접근권한은 직접 검증하세요.

## 개인정보·운영 주의
- 실명·면접 시각은 개인정보이므로 원칙적으로 회사 승인 계정과 제한된 공유 설정에서만 운영
- 이 기능은 임의의 다른 앱으로 지원자 상세 데이터를 전송하거나 공개 웹 API를 열지 않음
- JSON은 GitHub 저장소에 절대 올리지 않음
- 지원자 개인정보 삭제·전형 종료·일정 취소가 원본에서 바뀌면 다음 내보내기에서 갱신될 수 있으나, 기존 Drive 파일 사본/버전 이력 보존은 별도 관리
- 정상 동작 테스트는 실제 PC SQLite와 Drive 동기화 환경에서 수행해야 함
