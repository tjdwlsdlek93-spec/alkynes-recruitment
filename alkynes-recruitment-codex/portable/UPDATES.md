# 앱 업데이트 배포

이 기능을 처음 설치할 때는 Windows ZIP을 한 번 설치해야 합니다. 이후에는 설정 → 앱 업데이트에서 공개 GitHub 저장소를 지정하고 업데이트 확인 → 새 버전 업데이트를 누릅니다. 저장소 변경 시 설정에서 수정할 수 있습니다. GitHub 토큰을 앱에 넣지 않습니다. 비공개 저장소는 현재 지원하지 않습니다.

현재 패키지는 배포 주소가 연결되지 않은 상태입니다. GitHub 정식 릴리스와 아래 두 asset을 공개한 뒤 앱에 `소유자/저장소`를 입력해야 합니다. 빈 저장소·릴리스 누락·네트워크 실패는 오류로 표시하며 최신 버전이라고 잘못 표시하지 않습니다.

## 릴리스 만들기

루트 `.github/workflows/recruitment-release.yml`은 `recruitment-v2026.10.14.5` 같은 태그를 푸시할 때 테스트·정적 빌드·업데이트 파일 생성 후 GitHub 릴리스를 만듭니다. 먼저 이 소스와 워크플로를 저장소에 반영해야 합니다. 다음 배포에는 설치된 버전보다 큰 숫자 버전을 사용합니다. 현재 버전은 `portable/version.json`에 있습니다.

수동 배포 시 다음 명령으로 Windows 패키지 폴더에서 업데이트 파일만 생성합니다:

```
node scripts/package-update.cjs /path/to/windows-package /path/to/release
```

생성한 `alkynes-update.json`, `alkynes-update.json.gz`를 같은 최신 정식 릴리스의 assets로 업로드합니다. gzip 파일은 앱 화면·서버 코드·버전만 포함합니다. PC별 연결 경로, config, 브라우저 데이터, Node 런타임, 이력서·Excel 원본은 포함하지 않습니다.

## 적용 방식

설정에 지정한 공개 GitHub 저장소의 최신 릴리스만 읽습니다. HTTPS 주소와 파일 크기를 제한하고 SHA-256을 검증합니다. 파일 경로를 검증하여 허용된 앱 파일만 staging에 기록합니다. 현재 실행 중인 worker가 서버 종료 후 앱을 교체하며 config·Node 런타임은 교체하지 않습니다. 새 버전 health 응답을 확인한 뒤 완료 처리하며, 실패하면 이전 앱을 복원합니다. 최근 이전 버전은 `.updates/previous`에 남습니다. 프로세스 강제 종료나 전원 차단 중 파일 교체까지 보장하는 방식은 아닙니다.

브라우저 데이터와 연결 설정은 같은 주소에서 유지됩니다. 업데이트 전에 설정 → 데이터 백업을 사용할 수 있습니다. 실제 Windows 설치·보안 정책·재부팅은 회사 PC에서 확인해야 합니다.
